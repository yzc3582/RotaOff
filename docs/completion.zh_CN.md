# Completion（完成度）修复记录

> 面向开发者的踩坑记录；`README` 只链一句说明，完整来龙去脉在这里。
> 公式与数值表出自 [Rotaeno 中文维基「Completion」](https://wiki.rotaeno.cn/index.php?title=Completion)，

## 0. 现状（2026-11-09 收尾）

- **已与测试时的原版 QQ 侧 RotaBot 对齐**：同一份云存档，两边都是 `75.658/461 (16.412%)`。
- 与游戏内真值仍有差距，且**云存档缺少解锁/购买字段**导致差距无法消除（见 §5），**修复已放弃**。
- 因此 Completion **默认隐藏**：`output set completion on` 才输出，且每次输出都会附带误差警告
  （已解锁全部曲目的账号数值通常一致，可以放心参考）。

## 1. 现象

旧实现把「完成度」算成 `已游玩谱面数 / 曲库谱面总数`，任何账号都显示 `100%`。
换成真算法后本机显示 `75.658/461 (16.412%)`；对**同一份云存档**，游戏内显示 `43.638/463 (9.425%)`。
两个数字都不对，方向相反：分子偏大、分母偏小。

## 2. 根因

**100% 的来源**：云存档的 `songDatas` 不是「玩过的谱面」，而是**全部谱面各一条记录**，
没打过的 `score = 0 / status = NONE` 也在里面。所以 `len(songDatas)` 恒等于曲库总谱面数
（当时是 1770），相除必然得 1.0。

**为什么必须自己算**：`playerInfo` 里没有官方 Completion 字段（客户端自算，不上传），
上游 `rotaeno/` 也完全没有这块逻辑。想拿到真值只能按维基公式重算。

## 3. 算法（维基）

单谱面：

```
C_chart = min(1, 0.925 × R_chart / (D + 3.6) + B_score + B_flag)
```

- `R_chart`：该谱面当前成绩的单谱面 Rating（**现算**，理由见 §4）
- `D`：谱面定数；`D + 3.6` 是理论最高单谱 Rating
- `B_score`：1,008,000 起分档，1,010,000 封顶 `0.05`
- `B_flag`：`FC = 0.01`、`AP = 0.02`、`理论值 = 0.025`，取达成过的最高档

单曲（`W_d` = 0.7 / 0.8 / 0.9 / 1.0）：

```
C_single = max(0.7·C_I, 0.8·C_II, 0.9·C_III, C_IV) + C_IVα
```

总 Completion = ΣC_single；理论 Completion = 计入的 IV 与 IV-α 谱面数
（当前版本固定，不随购买/解锁变化）。中间计算不做取整，只在显示时保留三位小数，
舍入方式是**四舍六入五成双**（银行家舍入，正好是 Python `round()` 的默认行为）。

自检：理论值成绩一份谱面应得 `0.925 + 0.05 + 0.025 = 1.0`，已用满分谱验证通过。

## 4. 实现

`rotaoff/completion.py`，纯计算、不碰网络和文件：

| 函数 | 作用 |
| --- | --- |
| `score_bonus(score)` | `B_score` 分档表 |
| `chart_completion(chart)` | 单谱面 Completion |
| `completion_from(song_datas)` | `(当前, 理论)` |
| `format_completion(song_datas)` | `75.658/461 (16.412%)` |

`data.metrics_from()` 先 `exclude_retired()` 再调用 `format_completion()`，
并删掉了原来的 `total_chart_count()` 和散在 `data.py` 里的那份拷贝。

**不读 `ratingMix`**：上游为了 B40 会把「IV-α 高于 IV 时」的 IV Rating 置 0，
读它会低估难度 IV 的完成度；这里一律用 `calculate_song_rating()` 现算。

**默认隐藏**：`output.completion` 默认 `false`。显示时标签直接写「完成度（可能有偏差）」，
并在每次输出前附一条警告（`data/i18n/*.json` 的 `completion-caveat`）。
`custom completion` 在开关关闭时直接报错（`completion-hidden`），不做静默降级。

## 5. 已知差异（未解决，缺数据）

### 5.1 分子：75.658 vs 游戏 43.638

维基写明「若谱面未解锁，则该谱面不参与当前 Completion 计算」。而云存档**没有任何解锁/购买字段**：
`songDatas` 只有 `diff / id / isCleared / isFavorite / level / nextPointScore / rating / ratingMix / score / status / title`，
`status = NONE` 只表示「没成绩」，无法区分「买了没打」和「没买但活动期打过」。

于是实现里只能把「已解锁」近似成 `score > 0`，结果是**上界**。典型反例：测试账号 B40 里的
《Secret Illumination (seatrus's "The AURA" Remix)》，是活动期打过的、并没有解锁。
该账号 97 首已游玩曲目里，需要约 35 首属于此类才能解释掉 32.02 的差额。

排查过的替代口径（均不吻合 43.638）：只算 IV 谱（54.79）、只算 isCleared 的 IV 谱（51.64）、
`(R-D)/3.6`（55.74）、分母换成全曲最高定数（70.37）、再乘一次 0.925（69.98）。
说明误差不是单个常数偏移，而是「哪些谱面参与」这一层的信息缺失。

### 5.2 分母：461 vs 463

库内 429 首（434 减去 5 首下架曲）+ 32 张 IV-α = 461，维基 v2.99.0 记 463。
差额 2 张疑似出在**下架判定范围**：`KING` / `ラグトレイン` 下架后，它们的 IV-α 是否一起排除，
以及维基表格里 465 → 463 的口径。未定论。

### 5.3 可以补的数据源（暂缓）

维基「曲目列表」页能标出活动曲，但活动曲**本身也是可以解锁的**（测试账号就有 Flashdance、
Love Splash、伊天珀凌）。要把「未解锁」判准需要人工维护的拥有曲目清单，
成本高于收益，先停在「上界 + 文档说明」。

## 6. 曾计划做的标定实验（已放弃）

放弃原因：**云存档里缺少「是否解锁 / 是否购买」这类字段**，维基那条「未解锁不参与」在数据层面无从判定，
分子偏高是结构性问题，再做标定也修不掉。分母另有 2 张的不确定性（461 vs 463）。
原版 RotaBot 只输出分子（`75.658`），大概也是为了回避分母这个问题；
本实现仍显示 `分子/分母 (百分比)`，但默认隐藏。

顺带记一笔：`75.658` 是**分子**不是百分数，百分比是 `16.412%`——最初连这一点都被误读过。

原计划（只用于验证单谱面公式，与上文的分子偏差无关）：`Cryogenic` 四个难度 `score` 全为 0
（已解锁未游玩），当前对分子的贡献恰好是 0，但已占 1 位分母。打一次它的 **IV**，
记录成绩与打前/打后的游戏内 Completion，两者之差就是该谱面的真实 `C_chart`，
可以一刀切开「单谱面公式错」还是「参与谱面集错」。

预期（`D = 13.0`，1,000,000 分）：`R = 15.0` → `0.925 × 15 / 16.6 ≈ 0.836`，
`B_score = 0`（未到 1,008,000），Completion 应从 `43.638` 涨到约 `44.474`。

顺带还能回答维基没写清的一点：**已解锁但未通关的谱面，游戏给 0 还是给基础值**。
