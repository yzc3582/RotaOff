# BREAK指令：让AI立马停工
要去吃饭、睡觉、出门等使用。

# BREAK / RESUME 指令（最高优先级）

## 一、触发规则
- 用户输入独立词 `BREAK`、`暂停`、`停工`，或说“BREAK，我去吃饭/睡觉/出门”等：立即进入停工流程。
- 用户输入 `RESUME`、`复工`、`继续`：进入复工流程。
- `BREAK` 优先级高于当前任务：收到后不得继续原任务、不得开启新任务、不得规划下一步执行。
- 停工期间保持 `PAUSED` 状态，不自动复工，不响应新任务，除非用户明确说“取消BREAK”或“RESUME”。

## 二、BREAK 停工时做以下事情
1. **立即停止**：停止生成原任务内容，停止规划，停止发起新的工具调用、子任务、后台任务；不执行测试、构建、安装、提交、删除、回滚等操作。
2. **处理进行中的工具调用**：若工具可中断则立即中断；若不可中断，则等当前调用返回后立刻停止，不再发起任何新调用。
3. **保存状态快照**：优先写入 `.agent/BREAK_STATE.md`；若不可写，则在对话中输出完整【BREAK快照】，不得省略。
4. **快照必须包含**：任务目标、当前进度、已完成事项、未完成事项、下一步动作、关键文件/路径、关键命令、变量/配置、风险与待确认问题、最后更新时间。
5. **输出简短停工报告**：说明已停止、快照位置、下一步是什么、如何复工。
6. **标记状态**：`PAUSED`，然后等待复工指令，不继续任何工作。

停工报告模板：
【BREAK已触发｜状态：PAUSED】
已停止：当前任务与所有新动作
快照：已保存到 .agent/BREAK_STATE.md / 已在下方输出
下一步：……
复工请说：RESUME

## 三、RESUME 复工时做以下事情
1. **确认复工**：读取 `.agent/BREAK_STATE.md` 或对话中的【BREAK快照】；若快照不存在，先报告并请用户补充，不得假装恢复。
2. **检查变化**：只读检查关键文件、环境、依赖、git 状态等是否与快照一致；有冲突先报告，不擅自覆盖。
3. **输出恢复摘要**：任务目标、当前进度、已完成、未完成、下一步、风险。
4. **恢复执行**：默认从“下一步动作”继续，不重复已完成步骤，不重复调用有副作用的工具。
5. **遇到风险先确认**：若目标变化、文件冲突、需要副作用操作或信息不足，先询问用户，不擅自继续。
6. **状态改为**：`RUNNING`。

复工报告模板：
【RESUME｜已恢复】
读取快照：成功
当前进度：……
下一步：……
风险/待确认：……
现在从下一步继续。

## 五、禁止事项
- BREAK 后不得继续输出原任务内容。
- 不得自动复工。
- 不得删除文件、回滚代码、提交变更，除非用户明确要求。
- 不得把“保存状态”扩大成继续执行任务。
